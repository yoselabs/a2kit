## Why

a2kit's internal import-graph DAG exists only implicitly. It is encoded in `packages/lint/layers.py` and enforced by the `A2K-LAYER` rule, but it is never *rendered*. There is no agent-loadable or human-readable view of which units depend on which, each unit's fan-in / fan-out, or where a unit sits in the layer order. ADR 0007 established exactly this pattern for architecture decisions — the auto-generated `docs/adr/INDEX.md`, loaded once to see every decision. The component graph deserves the same treatment: a generated, always-current map that an agent or a human can load to understand the architecture without tracing imports by hand.

## What Changes

- New generator `scripts/component_map.py`: reads the layer manifest (`packages/lint/layers.py`) and the actual source import graph, and emits a markdown component map — every unit, its layer, its dependencies, its fan-in / fan-out, and the layer-ordered DAG.
- New generated document `docs/COMPONENT_MAP.md` — agent-loadable, the structural sibling of `docs/adr/INDEX.md`.
- New `make component-map` target that runs the generator.
- A pre-commit hook regenerates the map and fails the commit if the committed file is stale — the same staleness-gate mechanism `adr-index` already uses.

This change adds no enforcement: `A2K-LAYER` already polices the graph. The component map is a *view*, not a gate on imports — its only gate is staleness of the generated file.

## Capabilities

### New Capabilities

- `component-map`: an auto-generated, always-current rendering of the internal import-graph DAG — units, layers, dependency edges, fan-in / fan-out — regenerated by a pre-commit staleness gate.

### Modified Capabilities

None.

## Impact

- **Code:** new `scripts/component_map.py`.
- **Build:** new `make component-map` target; new entry in `.pre-commit-config.yaml`.
- **Docs:** new generated `docs/COMPONENT_MAP.md`.
- **Source of truth:** the generator reads `packages/lint/layers.py`; it does not duplicate the manifest. After the `split-app-runtime` change lands, the map automatically reflects the `kernel` / `authoring` / `runtime` sub-units.
